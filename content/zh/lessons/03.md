# 03 批量重命名：字符串处理、`Path.rename`、先预览再执行

> 这一节讲批处理的第 2、3 步：算出新名字，然后真正改名——但**先打印计划，确认无误再动**。

## 算出新名字

重命名本质是**字符串变换**。比如把「报告_2024.pdf」改成「2024-报告.pdf」：

```python
from pathlib import Path

def new_name(p: Path) -> str:
    name, sep, ext = p.stem.rpartition("_")
    if not sep:
        return p.name  # 没有下划线，保持原样
    return f"{ext}-{name}{p.suffix}"
```

`str.rpartition("_")` 从右边切一刀，返回 `(前缀, 分隔符, 后缀)`。用 `rpartition` 而不是 `partition`，是为了处理「报告_终版_2024.pdf」这种含多个下划线的情况。

## 真正改名

```python
p = Path("报告_2024.pdf")
p.rename(p.with_name(new_name(p)))
```

`Path.rename(target)` 接收**完整目标路径**。用 `with_name` 只换文件名、保留所在目录，最安全。

## 先预览再执行

这是本课最重要的安全习惯：

```python
from pathlib import Path

dry_run = True  # 先 True 跑一遍预览
for p in Path(".").glob("*.pdf"):
    target = p.with_name(new_name(p))
    if dry_run:
        print(f"[预览] {p.name} -> {target.name}")
    else:
        p.rename(target)
```

把 `dry_run = True` 跑一遍，看清每个文件会怎么变；确认没问题再把 `dry_run` 改成 `False`。

## 翻车现场

```python
# 想给所有文件加前缀「bak_」，写了：
for p in Path(".").iterdir():
    p.rename("bak_" + str(p))
# 报错？不一定。但即使不报错，你也可能：覆盖了同名文件、把目录也改了、路径写错。
```

**后果**：数据被覆盖、脚本报错中断、改出一堆乱码文件名。**没有预览就直接 rename，等于闭着眼过马路**。

## 防覆盖小技巧

改名前检查目标是否已存在：

```python
if target.exists():
    print(f"跳过 {p.name}，目标已存在")
    continue
p.rename(target)
```

## 小结

- 重命名 = 字符串变换 + `Path.rename`
- 用 `rpartition` 处理多分隔符
- 永远先 `dry_run` 预览
- 检查目标是否已存在，避免覆盖
