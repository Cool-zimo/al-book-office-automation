# 01 为什么自动化：手动改 200 个文件名要多久

> 这一节帮你算清一笔账：重复劳动到底浪费了多少时间，以及自动化脚本是怎么把这件事变简单的。

## 一个真实场景

张三在行政岗，月底要把「销售报告_202409.pdf」「销售报告_202410.pdf」……一共 200 个文件，统一改成「202409-销售报告.pdf」这样的格式。他右键→重命名→改完一个大约 8 秒，中间走神、改错还要撤销。200 个文件就是 1600 秒，接近半小时，还**不算检查的时间**。

换成一行 Python：

```python
from pathlib import Path
for p in Path(".").glob("*.pdf"):
    name, _, ext = p.stem.rpartition("_")
    new = p.with_name(f"{ext[1:]}-" + name + ext if False else p.stem.split("_")[1] + "-" + p.stem.split("_")[0] + ".pdf")
    p.rename(new)
```

十几行代码，半秒跑完，零差错。这就是自动化的意义：**把人从重复、易错、机械的操作里解放出来**。

## 自动化的三个步骤

任何批处理任务都可以拆成三步：

1. **找到目标**：哪些是我要处理的文件（遍历目录、过滤后缀）
2. **计算新状态**：新的名字、新的位置、新的内容是什么（字符串处理、数值计算）
3. **执行并验证**：改名字、移动、写文件，最后核对一遍结果

后面 9 节课，就是在反复练这三步。

## 自动化不是「一次写对」

新手最容易犯的错，是**直接对着真实文件跑脚本**。一个 `rm -rf` 写错路径，删掉的是三年账本。正确姿势是：

- 先用 `print` 把「计划做什么」打出来
- 确认无误，再把 `print` 换成真正的操作
- 处理前先备份，或者在一个**副本目录**里跑

## 翻车现场

```python
# 想删掉所有 .tmp 文件，结果写成了：
for f in os.listdir("."):
    if f.endswith(".tmp"):
        os.remove(f)
# 看起来没问题？但如果当前目录是 HOME，且你手滑把 ".tmp" 写成了 ""，
# endswith("") 永远为 True，后果不堪设想。
```

**后果**：误删文件、覆盖数据、脚本跑飞。自动化的威力越大，出错的代价也越大。

## 小结

- 批处理 = 遍历 + 计算 + 执行，三步循环
- 永远**先预览再执行**，处理副本或先备份
- 重复劳动超过 5 次，就值得写个脚本
