# 01 Why Automate: How Long to Rename 200 Files Manually

> This lesson helps you do the math: how much time repetitive work really wastes, and how a script makes it trivial.

## A Real Scenario

Alice works in admin. At month end she has to rename 200 files like `report_202409.pdf`, `report_202410.pdf` ... into `202409-report.pdf`. Right-click, rename, about 8 seconds each. Distractions and typos add up. 200 files = 1600 seconds, almost half an hour — and that's **not counting verification**.

In Python it's a few lines:

```python
from pathlib import Path
for p in Path(".").glob("*.pdf"):
    name, _, ext = p.stem.rpartition("_")
    new = p.stem.split("_")[1] + "-" + p.stem.split("_")[0] + ".pdf"
    p.rename(new)
```

Runs in half a second, zero errors. That's the point of automation: **freeing people from repetitive, error-prone, mechanical work**.

## The Three Steps of Automation

Every batch job breaks down into three steps:

1. **Find targets**: which files to process (traverse, filter by extension)
2. **Compute the new state**: what's the new name, location, content (string ops, arithmetic)
3. **Execute and verify**: rename, move, write, then double-check

The next 9 lessons are just repeated practice of these three steps.

## Automation Is Not "write it once, get it right"

The classic beginner mistake is **running the script against real files immediately**. One wrong `rm -rf` and you've deleted three years of accounting. The correct posture:

- First `print` what you *plan* to do
- Once it looks right, swap `print` for the real operation
- Back up first, or run on a **copy directory**

## Crash Scene

```python
# Wanted to delete .tmp files, but wrote:
for f in os.listdir("."):
    if f.endswith(".tmp"):
        os.remove(f)
# Looks fine? But if cwd is HOME and you typo ".tmp" as "",
# endswith("") is always True. Catastrophic.
```

**Consequence**: deleted files, overwritten data, runaway scripts. The more powerful the automation, the higher the cost of a mistake.

## Summary

- Batch processing = traverse + compute + execute, on repeat
- Always **preview then execute**; work on copies or back up first
- If you repeat a task more than 5 times, it deserves a script
